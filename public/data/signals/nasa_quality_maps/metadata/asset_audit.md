## 2. Class Code → Name Verification

Detected unique values in `dominant_class_daytime.tif`: **[0, 1, 2, 4, 5, 6, 7, 8]**

| Code | Name in CLASS_CODE_TO_NAME | Status | Notes |
|---|---|---|---|
| 0 | unclassified | MAPPED | Rendered transparent, not in legend |
| 1 | stable_core | MAPPED | ~6.7 km², ~3.8% |
| 2 | coherent_activation | MAPPED | ~0.9 km², ~0.5% |
| 3 | strong_activation | ABSENT from daytime | Present only in midday raster; code exists in dict |
| 4 | esi_watch | MAPPED | ~10.9 km², ~6.2% |
| 5 | demand_efficiency_watch | MAPPED | ~50.7 km², ~29.0% |
| 6 | efficient_activation | MAPPED | ~4.8 km², ~2.7% |
| 7 | disagreement | MAPPED | ~87.9 km², ~50.3% |
| 8 | high_variability | MAPPED | ~9.6 km², ~5.5% |
| 255 | nodata | HANDLED | Converted to NaN; rendered transparent |

**Note on code 3 (strong_activation):** Absent from daytime, daytime_evening, and all_available rasters. Present only in midday_afternoon. This is expected — the class requires both NDVI and ET slopes to fall in the upper activation range, a more stringent condition met by fewer pixels at tighter temporal filters.
